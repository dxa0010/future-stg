# RESONANCE FLICK

縦スクロール・ローグライトSTG のたたき台（プロトタイプ v1）。
仕様は [`docs/SPEC.md`](docs/SPEC.md)。

**遊ぶ：** https://dxa0010.github.io/future-stg/
（スマホ推奨。PC ではマウスドラッグ、または WASD/矢印 + Shift + Space）

---

## 操作

| 操作 | 状態 | リスク | リターン |
|---|---|---|---|
| 仮想スティック | 触った場所に出る。倒した向きへ移動＋自動射撃 | なし | — |
| 回避ボタン（左下） | 攻めの回避。**進んでいる向き**へ 8方向スナップ・固定距離 | スタミナ消費、通路を抜けた後は無防備 | 経路の弾を弾く／ジャスト成立で瞬炎 |
| 指を離す | 完全静止して溜め | 射撃停止、被弾で溜め全消滅 | 解放で臨界共鳴 |
| 解放ボタン（右下） | 臨界共鳴 | 溜めを消費 | 極太ビーム＋弾消し衝撃波＋ジェム吸着 |

移動は既定で**フローティングの仮想スティック**。画面のどこを触ってもそこが支点になり、
倒しきると支点が指を追いかける。タイトルとポーズから**ドラッグ方式**（指の動きと自機が 1:1）に
切り替えられる。

回避ボタンの矢印が「いま押したらどっちへ飛ぶか」を示す。ボタンのリングはスタミナの回復、
下の点は残ストック。方向は自機の進行方向なので、**曲がりたい向きへ指を振ってから押す**。

回避は弾幕へ突っ込むための行動になっている。

| 区間 | 挙動 |
|---|---|
| 開始〜7F（無敵） | 敵弾と重なると**ジャスト成立** → 通過軌跡上の弾を消す＋瞬炎＋スロー |
| 8F〜18F | 通る経路の敵弾を**弾き飛ばす**（消えない。0.4 秒だけ無害になって自機から離れる） |
| 着地後 | 無防備。弾いた弾もやがて危険に戻る |

無敵中は元々当たらないので弾く必要がなく、そこで掃くと「無敵中に弾と重なる」＝
ジャスト回避が成立しなくなる。だから弾くのは無敵が切れてから（＝着地点まわり）だけにしている。

ジャスト成立時の見返り：ヒットストップ 3F →**スロー 13F**、放射状の火花と白フラッシュ、
スタミナ即回復、瞬炎。瞬炎中は**自機と自弾が熱色**になり、自機のリングが残り時間を示す。
瞬炎が続く間に連続で決めると**連続数**が伸び、演出・音程・スコアが上がる
（仕様どおり**瞬炎の効果自体は重ねがけしない**）。

スワイプでの回避も残してあり、タイトルとポーズから ON/OFF できる（既定は OFF）。
通常の移動で暴発してスタミナを食うのが気になる場合は OFF のまま、
仕様書の「フリック回避」を試したいときだけ ON にする。

PC 用：`WASD` / 矢印で移動、`Shift`（または `Z`）で回避、`Space`（または `X`）で解放。
移動キーを離している間が「指を離している」状態＝溜めになる。

## 実装済み（プロトタイプ範囲）

- **3つの状態**：ドラッグ／フリック／指離し。ヒートゲージは無し
- **回避**：8方向スナップ、固定距離（画面幅25%）、モーション18F・無敵7F、画面端で停止
- **ジャスト回避**：無敵中に敵弾・レーザー・接触判定と重なると成立 → ヒットストップ3F、金属音、スタミナ即回復、軌跡上の弾消し、瞬炎（攻撃力・連射・貫通）
- **溜め**：指離しで即開始、9F 未満は誤タッチ扱い、**繰り越し保持**、被弾で全消滅、保持中はオーラで常時可視化
- **解放ボタン**：溜め保持中だけ表示。段階で色・大きさ・リングが変化。フリック直後 6F は無効
- **臨界共鳴**：段階別の極太ビーム／衝撃波／弾消し（段階2以上）／ジェム吸着
- **成長**：ジェム → レベルアップ → 3択。パッシブ8種＋汎用強化
- **進化武器**：ヴォルテックスストーム（ガトリング＋ブーストアクセルLv3）、絶対零度・オメガカノン（集束ビーム＋コンデンサーLv3）
- **究極進化**：ディメンション・リフレクター（熟練度が回避・溜めの両方で高水準、かつベース進化済みのときだけ3択に出現）
  - 回避の弾きが**敵へホーミングする反転弾**になる
  - ジャスト成立から 0.5 秒、当たった弾を**被弾にせず撃ち返す**「反射窓」
  - 溜め中に吸収したストックを、回避入力で**上方向中心の扇状レーザー**（3〜9本・必ず奇数）に解放
  - 詳細は [`docs/SPEC.md`](docs/SPEC.md) の「究極進化」節
- **イージスフィールド**：オメガカノン取得後のみ抽選に出る。溜め成立中の被弾のみ無効化、次ステージで回数リセット
- **ボス**：中ボス（ステージ1）・ボス（ステージ2）。部位破壊でパターン変化、コア露出でダメージ倍率解除
- **敵5種**：直進 / 蛇行 / シールド（貫通・臨界共鳴で無効化できる正面シールド）/ 突撃 / 固定砲台
- **残機制**：被弾で −1、溜めは同時に全消滅。残機アイテムをステージ内に配置
- **その他**：CRT フィルター、音のON/OFF、ポーズ、シード指定

## 設計

```
src/
  sim/        シミュレーション層（Pixi にも DOM にも依存しない純粋な TS）
    constants.ts  仕様の数値をすべてフレーム単位で定義
    rng.ts        決定論的乱数（mulberry32）
    world.ts      ゲームロジック本体。update(InputFrame) を 60Hz で呼ぶだけ
    enemies.ts    敵AI・ボス
    stage.ts      ウェーブ定義
    upgrades.ts   3択の抽選と適用
  render/     Pixi v8 の描画層（World を読むだけ。逆方向の依存はない）
  input/      ポインタ／キーボード → InputFrame
  audio/      WebAudio による効果音合成（アセット無し）
  ui/         DOM のオーバーレイ（タイトル・3択・リザルト・解放ボタン）
```

- **固定タイムステップ**：ロジック 60Hz、描画は可変。`main.ts` のアキュムレータで分離
- **決定論**：`Math.random` はシミュレーション内で一切使わない。シードと入力列が同じなら結果は必ず同じ
- **ゴーストリプレイ**：入力列（`InputFrame[]`）を保存するだけで再生できる。デバッグ用に `window.game.replay` で参照可能
- 画像アセットは持たず、`Graphics` から実行時にテクスチャを焼いている

## 開発

```bash
npm install
npm run dev        # 開発サーバ
npm run typecheck  # tsc --noEmit（strict）
npm test           # 決定論テスト＋仕様数値の検証
npm run balance    # ボットに通しプレイさせてバランスを見る
npm run measure    # 究極進化などの実効ダメージを測る
npm run build      # 本番ビルド
```

`main` に push すると GitHub Actions が typecheck → test → build → GitHub Pages に公開する。

初回だけリポジトリの **Settings → Pages → Build and deployment → Source** を
**GitHub Actions** に変更しておく必要がある。
（ワークフローの `GITHUB_TOKEN` では Pages サイトを新規作成できないため、
`configure-pages` の `enablement` では代替できない）

### 決定論テスト（`npm test`）

同じシード＋同じ入力列で 2 回走らせ、位置・スコア・敵数・乱数状態まで一致することを確認する。
併せて「無敵 = 7F」「閾値 = 9F」など仕様の数値がフレームに落ちていること、
`Math.random` が使われていないこと、溜めの繰り越しと誤タッチ仕様も検証している。

### バランス検証（`npm run balance`）

2種類の簡易ボット（`safe`＝弾から逃げるだけ／`aggressive`＝弾に飛び込んでジャストを狙う）に
2武器 × 3シードで通しプレイさせ、所要時間・到達レベル・進化到達・被弾数を表で出す。
人力プレイの代わりにはならないが、桁が狂ったときに気づける。

現状の目安（`aggressive` で 6 回中 3 回クリア、`safe` は 0 回。1周 3〜4.5 分）。
5ステージ構成に伸ばすと仕様書の「12〜15分」に乗る想定。

## 検証で分かったこと（仕様書へのフィードバック）

1. **チャージ速度の乗算は上限が要る。**
   コンデンサー × オメガカノン（倍化）× オーバードライブ（3倍）が素直に乗ると 10 倍を超え、
   段階3が 0.3 秒で溜まる。「静止のリスク」が消えて溜めビルドが無敵になったため `CHARGE_RATE_CAP` を追加した。

2. **弾消しの範囲はダメージ範囲より狭くする必要がある。**
   解放のたびに広範囲の弾が消えると、溜めビルドが常時無敵になる。
   ダメージ範囲の 55%（`RESONANCE_CLEAR_RATIO`）に絞って「爽快だが安全ではない」状態にしている。

3. **特殊進化はベース進化の後に置くのが自然。**
   熟練度条件だけだと、ベース進化より先に特殊進化が出て本命ビルドを潰してしまう。
   「両方を極めた者に」という演出とも整合するので、ベース進化済みを条件に加えた。

4. **熟練度の閾値は仕様書の【仮】値のまま。**
   ボットは 90%超のジャスト成功率を出すので、上位10%の線引きは実プレイのデータが要る。
   `MASTERY_JUST_MIN` / `MASTERY_JUST_RATE` / `MASTERY_MAXCHARGE_MIN` を実測後に調整する。

5. **回避の方向（未決定事項1）は 8方向スナップのみ実装。**
   360度自由との比較はまだ。`snap8()`（`src/input/pointer.ts`）を差し替えれば試せる形にしてある。

6. **スワイプ回避は「移動」と入力が混ざる。**
   スワイプは自機を動かしながら回避も出すので、意図しない回避でスタミナが減り、
   狙って出している感覚が薄い。左下の回避ボタンに分離したところ、
   「指で向きを作る → ボタンで飛ぶ」と役割が分かれて狙いやすくなった。
   スワイプ側も残してあるので、両方を比べられる。

7. **60Hz 固定ステップは表示周期とのズレ対策が要る。**
   `deltaMS` をそのまま積むと、1 描画フレームで 0 ステップ／2 ステップが交互に起きて
   移動がガクつく。`snapDelta()`（`src/main.ts`）でステップ境界にスナップしている。
   なお描画側の補間は入れていない（補間すると 1 フレーム分の遅延が乗って逆効果）。

8. **回避の「弾き」とジャスト回避は判定範囲が食い合う。**
   回避の経路上の弾を弾くようにしたところ、無敵区間まで掃くと弾が先に散ってしまい、
   ジャスト回避（無敵中に弾と重なる）がほぼ成立しなくなった。
   無敵中は元々被弾しないので弾く必要がない、と整理して「無敵が切れてから掃く」に限定している。
   ボット計測では、この変更で上手い側の被弾が 4〜5 回から 0〜2 回に減った（クリア 4/12 → 6/12）。
   安全になりすぎるようなら `DODGE_DEFLECT_R` を絞るのが一番効く。

9. **スロー演出はロジックではなく「実時間の進み方」で入れる。**
   固定タイムステップなので、スローはロジック側のフレーム数（`slowmo`）で数え、
   描画ループがアキュムレータへ足す実時間だけを縮める。
   ステップ列は変わらないので決定論もリプレイも壊れない（テストで確認している）。

10. **オーバーレイの管理は「開いているか」ではなく「どの画面か」で持つ。**
   ボス撃破時の レベルアップ → ステージクリア のように画面から画面へ直接遷移する場面で、
   `画面が開いていたら何もしない` という条件だと描き直しが飛ばされて操作不能になった。
   `screenKey()` で「いま出すべき画面」を表し、変わったときだけ描き直す方式にしてある。
